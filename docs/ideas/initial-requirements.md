## プロダクトビジョン

有限会社山田田中商店のコーポレートサイトと、普段の仕事でよく使うWeb便利ツールを、1つのサイトにまとめる。社外には名刺代わりの最低限の会社情報を見せ、中身の大部分は自分たちが使うツール置き場として育てていく。

**一言で言うと**: 会社の名刺ページ付きの、自分用Webツール置き場

## 解決したい課題

### 今困っていること

1. **今のホームページが更新しづらく、内容も古い**
   - Googleサイト（https://sites.google.com/yamadentanaka.com/home）で公開している
   - 載っているのは「研究室（情報処理〈vim〉・ロボット・食）」とお知らせ2件（2017年）だけ
   - 会社名は出ているが、事業内容や実績が分からない
   - 見た目や内容を充実させたいが、Googleサイトでは自由が利かない

2. **よく使うちょっとした機能の置き場がない**
   - 仕事でたびたび必要になる処理を、その都度スクリプトを書いたり、ツールを探したりしている
   - 自分でコード管理できて、ブラウザを開けばすぐ使える場所が欲しい

3. **カメラ画像に判定エリアを設定するのが面倒**
   - 映像AIの仕事で、カメラ画像の上に「この範囲に入ったら検知する」といった判定エリア（ポリゴン）を設定する場面が多い
   - 頂点のピクセル座標を手で拾うのは手間がかかり、間違えやすい
   - アノテーションツールは機能が多すぎる。判定エリアを決めるだけなら、もっと軽い専用ツールが良い

### ツール第1弾: ポリゴンエリア定義ツール

カメラ画像を読み込み、その上にポリゴンを描いて判定エリアを定義し、JSONで出力するツール。

#### P0 (MVPで絶対必要)

1. **画像の読み込み**
   - ファイル選択と、ドラッグ&ドロップに対応
   - **画像はブラウザの外に送らない**（カメラ画像には現場の様子が写るため）
2. **ポリゴンの描画**
   - クリックで頂点を追加し、始点のクリックかEnterで閉じる
3. **複数エリア**
   - 1枚の画像に複数のエリアを設定できる
   - エリアごとに名前と色を付ける
4. **編集**
   - 頂点のドラッグ移動、頂点の追加・削除、エリアの削除
5. **拡大縮小・移動**
   - ホイールで拡大縮小、ドラッグで表示位置を移動
6. **カーソル位置のピクセル座標を表示**
7. **JSONのダウンロードと読み込み**
   - ダウンロードしたJSONを読み込んで、作業を再開できる
   - 座標は画像のピクセル座標

**JSONのイメージ**
```json
{
  "version": 1,
  "image": { "name": "cam01.jpg", "width": 1920, "height": 1080 },
  "areas": [
    { "name": "判定エリアA", "points": [[120, 340], [860, 320], [900, 1000], [100, 1020]] }
  ]
}
```

- 画像のサイズを含めておき、読み込む側で解像度が違う画像に使っていないかを確認できるようにする

#### P1 (重要だけど後回しでもいい)

- 元に戻す / やり直す
- JSONをクリップボードにコピー
- 読み込んだJSONの画像サイズが今の画像と合わないときの警告

#### やらないこと

- アノテーション（学習データ作成）用途。必要なら専用ツールを使う
- マスク画像の出力（今回は出力をJSONに絞った）

## 差別化ポイント

- **判定エリアを決めることだけに絞っている**: アノテーションツール（CVATやlabelmeなど）のように、ラベル管理やデータセット管理を覚える必要がない
- **インストール不要で、画像を外に出さない**: ブラウザだけで動き、画像はサーバーに送らない
- **出力したものを、そのままプログラムに使える**: ピクセル座標と画像サイズを持つ、シンプルなJSONを出力する
- **自分でコードを管理しているので、必要な機能を足していける**

## 技術的な検討事項

### サイトの作り方

ほぼ静的な会社ページと、ブラウザ内で完結するツール群なので、サーバー処理のない静的サイトとして作る。

| 案 | 構成 | 評価 |
|---|---|---|
| **A（採用）** | Astro + TypeScript。重い処理が必要なツールは、そこだけRust→WASMにする | 会社ページ・Markdownのメモ・ツールを1つのサイトで扱える。UI中心のツールはTSのほうが書きやすい |
| B | Rust製のフロントエンド（Leptos / Dioxus）で全部作る | Rustで統一できるが、会社ページやメモには大げさ |
| C | 会社ページは簡単なHTML、ツールは個別のRust WASMアプリ | 共通レイアウトを二重に管理することになる |

**結論**: A案。普段の主言語はRustだが、ポリゴンツールの中身はほぼ描画とマウス操作なので、TSで書く。将来、画像処理など計算が重いツールを作るときにRust/WASMを使う。

### ポリゴンツールの描画方法

- SVGかCanvasで、画像の上にポリゴンを重ねて描く（どちらにするかは設計で決める）
- 拡大縮小・移動をしても、座標は常に元画像のピクセル座標で扱う

### 公開方法

| 案 | 評価 |
|---|---|
| **GitHub Pages（採用）** | 無料で最も手軽。まずはここから始める |
| Cloudflare Pages | 無料。PRごとのプレビューURLや、アクセス制限（Cloudflare Access）が使える。物足りなくなったら移行を考える |
| AWS（S3 + CloudFront）/ GCP | 使ったことはあるが、この規模には設定が多すぎる |

- ツールは全公開で問題ない（画像はブラウザの外に出ないため、情報漏えいの心配がない）
- GitHubで管理し、GitHub Actionsでビルドして公開する想定

### ドメイン

- `yamadentanaka.com` は Google Workspace で使っている
- Webサイト用のレコード（`www` のCNAMEなど）を追加しても、メール（MXレコード）には影響しない
- 独自ドメインで公開できれば良いが、こだわりはない（`github.io` のURLから始めても良い）
- 新しいサイトを公開してから、Googleサイトを切り替える（または閉じる）
