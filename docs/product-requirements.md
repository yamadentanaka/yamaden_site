# プロダクト要求定義書 (Product Requirements Document)

## プロダクト概要

### 名称
**山田田中商店サイト** - コーポレートサイト兼Web便利ツール集

### プロダクトコンセプト
- **名刺代わりの会社ページ**: 社外の訪問者には、会社名・事業内容・実績・お知らせだけを簡潔に見せる
- **自分たちのツール置き場**: 仕事でよく使う処理を、ブラウザを開けばすぐ使えるWebツールとして追加していく
- **画像を外に出さない**: ツールはブラウザ内だけで処理し、読み込んだ画像やデータをサーバーに送らない

### プロダクトビジョン
有限会社山田田中商店のコーポレートサイトと、普段の仕事で使うWeb便利ツールを1つのサイトにまとめる。会社の情報は自分たちでコード管理し、必要なときにすぐ更新できる状態にする。ツールは、必要になった機能を1つずつ足していける構成にし、散らばっていたスクリプトや手作業を置き換えていく。第1弾として、カメラ画像に判定エリアを設定するポリゴンエリア定義ツールを提供する。

### 目的
- Googleサイトで公開している現在のホームページを置き換え、事業内容と実績が分かる会社ページにする
- カメラ画像の判定エリアの座標を手作業で拾う手間をなくす
- 今後のWeb便利ツールを追加していける土台を作る

## ターゲットユーザー

### プライマリーペルソナ: 代表・社内メンバー（映像AI・画像認識の研究開発者）
- 属性・利用環境: 有限会社山田田中商店の代表。映像AI・画像認識の研究開発をしている。PCのブラウザで使う
- 現在の課題:
  - カメラ画像に判定エリア（「この範囲に入ったら検知する」など）を設定するとき、頂点のピクセル座標を手で拾っていて、手間がかかり間違えやすい
  - アノテーションツールは機能が多すぎて、判定エリアを決めるだけの用途には重い
  - よく使う処理が、あちこちのスクリプトに散らばっている
- 期待する解決策: ブラウザを開けばすぐ使え、結果をJSONでそのままプログラムに渡せるツール
- 典型的な利用場面:
  1. カメラから取得した静止画をツールに読み込む
  2. 画像を拡大しながら、判定エリアのポリゴンを複数描く
  3. JSONをダウンロードし、検知プログラムの設定として使う
  4. 後日、エリアを調整するときは、同じ画像とJSONを読み込んで続きから編集する

### セカンダリーペルソナ: 社外の訪問者（取引先・依頼を検討している人）
- 属性・利用環境: 仕事の依頼や取引を検討していて、会社のことを知りたい
- 現在の課題: 今のホームページには研究室のページとお知らせ2件（2017年）しかなく、事業内容や実績が分からない
- 期待する解決策: どんな会社で、何をしていて、どんな実績があるかが分かる
- 典型的な利用場面: 名刺やメールの署名からサイトを開き、トップページで会社の概要と実績を確認する

## 成功指標(KPI)

### プライマリーKPI
- 判定エリアの設定をツールで行う割合: 100%（MVP公開日から3か月間） — 測定方法: 新しく判定エリアを設定した案件ごとに、代表が手元の記録に「日付・案件名・ツールを使ったか（使わなかった場合は理由）」を残し、期間の終わりに割合を出す。期間中に対象の案件が0件なら、1件以上になるまで期間を延ばす

### セカンダリーKPI
- ホームページの切り替え: 完了（MVP公開日から1か月以内） — 測定方法: 名刺・メール署名に載せるURLを、新しいサイトのURLに変更し終えたかを確認する。URLを変える前に、独自ドメインを使うかを決める（独自ドメインに移るとURLが変わるため。未決事項を参照）。Googleサイトを閉じるかどうかは、このKPIに含めない（未決事項を参照）

## 機能要件

### コア機能(MVP)

#### 1. トップページ（会社情報）

**ユーザーストーリー**:
社外の訪問者として、どんな会社かを知るために、会社名・事業内容・実績・お知らせを1ページで見たい

**受け入れ条件**:
- [ ] 会社名「有限会社山田田中商店」が表示される
- [ ] 事業内容として、次の文が表示される: 「顧客企業の研究開発チームに参画し、AI・DX分野の研究開発を支援しています。画像認識、生成AI、レコメンド、データ基盤などを、技術検証から本番運用まで担当します。」
- [ ] 実績が、年と内容の一覧で表示される（載せる範囲は未決事項を参照。0件なら実績の見出しごと表示しない）
- [ ] お知らせが、日付の新しい順に表示される（0件ならお知らせの見出しごと表示しない）
- [ ] 実績とお知らせは、ページのレイアウトを変えずにデータの追加だけで増やせる

**優先度**: P0(必須)

#### 2. ツール一覧ページ

**ユーザーストーリー**:
社内メンバーとして、使いたいツールをすぐ開くために、ツールの一覧ページが欲しい

**受け入れ条件**:
- [ ] 公開しているツールが、名前と短い説明付きで一覧表示される
- [ ] 一覧からクリックすると、各ツールのページが開く
- [ ] ツールを追加するとき、既存のツールのコードを変更せずに一覧へ追加できる

**優先度**: P0(必須)

#### 3. 共通レイアウト

**ユーザーストーリー**:
訪問者として、サイト内を迷わず移動するために、全ページで同じヘッダー・ナビゲーション・フッターが欲しい

**受け入れ条件**:
- [ ] 全ページに、同じヘッダー・ナビゲーション・フッターが表示される
- [ ] ナビゲーションから、トップページとツール一覧ページに移動できる

**優先度**: P0(必須)

#### 4. ポリゴンエリア定義ツール: 画像の読み込み

**ユーザーストーリー**:
社内メンバーとして、カメラ画像に判定エリアを設定するために、画像をツールに読み込みたい

**受け入れ条件**:
- [ ] ファイル選択ダイアログから画像を読み込める
- [ ] 画像ファイルを画面にドラッグ&ドロップして読み込める
- [ ] 読み込んだ画像がどこにも送信されない（画像を読み込む直前から、エリア定義JSONのダウンロード・読み込みを含む操作を終えるまでに、配信元を含む全ての宛先への http・https のリクエストが0件であることを、E2E テストで確認できる。`blob:`・`data:` は数えない）

**優先度**: P0(必須)

#### 5. ポリゴンエリア定義ツール: ポリゴンの描画と複数エリア

**ユーザーストーリー**:
社内メンバーとして、1枚のカメラ画像に複数の判定エリアを設定するために、名前と色の付いたポリゴンを複数描きたい

**受け入れ条件**:
- [ ] 画像上をクリックすると、その位置に頂点が追加される
- [ ] 頂点が3つ以上のとき、始点をクリックするかEnterキーを押すと、ポリゴンが閉じて1つのエリアになる。頂点が2つ以下のときに始点をクリックするかEnterキーを押すと、確定せず（頂点も追加せず）、通知を表示する
- [ ] 1枚の画像に、複数のエリアを作れる
- [ ] エリアごとに名前を付けられる
- [ ] エリアごとに色が付く。10エリアまでは、全てのエリアが違う色になる（11エリア目からは色が重なってよい）

**優先度**: P0(必須)

#### 6. ポリゴンエリア定義ツール: エリアの編集

**ユーザーストーリー**:
社内メンバーとして、描いた判定エリアを調整するために、頂点やエリアを編集したい

**受け入れ条件**:
- [ ] 頂点をドラッグして移動できる
- [ ] 既存のエリアに頂点を追加できる
- [ ] 既存のエリアから頂点を削除できる
- [ ] エリアを削除できる

**優先度**: P0(必須)

#### 7. ポリゴンエリア定義ツール: 拡大縮小と座標表示

**ユーザーストーリー**:
社内メンバーとして、細かい位置まで正確に頂点を置くために、画像を拡大して、カーソル位置のピクセル座標を確認したい

**受け入れ条件**:
- [ ] マウスホイールで画像を拡大・縮小できる
- [ ] ドラッグで表示位置を移動できる
- [ ] カーソル位置の、元画像のピクセル座標が表示される
- [ ] 拡大・縮小・移動をしても、エリアの座標は元画像のピクセル座標のまま変わらない

**優先度**: P0(必須)

#### 8. ポリゴンエリア定義ツール: エリア定義JSONの出力と読み込み

**ユーザーストーリー**:
社内メンバーとして、判定エリアを検知プログラムに渡し、後から編集を再開するために、エリアをJSON（エリア定義JSON）でダウンロードし、読み込み直したい

**受け入れ条件**:
- [ ] 設定したエリアを、エリア定義JSONのファイルとしてダウンロードできる
- [ ] エリア定義JSONには、画像のファイル名・幅・高さと、各エリアの名前と頂点のピクセル座標が含まれる
- [ ] ダウンロードしたエリア定義JSONを読み込むと、エリアが画像上に復元され、続きから編集できる
- [ ] 同じ画像を読み込んだ状態で、ダウンロード → 読み込み → ダウンロードをしたとき、ファイルの内容が完全に一致する
- [ ] エリア定義JSONの画像の幅・高さが、読み込んでいる画像と違うときは、エリアを読み込まず、両方のサイズを示すエラーを表示する

**JSONの形式（イメージ。正確な出力形式は機能設計書を参照）**:
```json
{
  "version": 1,
  "image": { "name": "cam01.jpg", "width": 1920, "height": 1080 },
  "areas": [
    { "name": "判定エリアA", "points": [[120, 340], [860, 320], [900, 1000], [100, 1020]] }
  ]
}
```

**優先度**: P0(必須)

#### 9. ポリゴンエリア定義ツール: 操作説明

**ユーザーストーリー**:
初めてツールを使う社内メンバーとして、説明書を探さずに使い始めるために、ツールの画面で操作方法を確認したい

**受け入れ条件**:
- [ ] ツールのページに、画像の読み込み・エリアの描画・編集・名前の変更・拡大縮小と移動・保存と再開の操作方法が表示される
- [ ] キー操作（N / Enter / Esc / Backspace / Delete / 0 / Space）とダブルクリックでの頂点の追加が、操作説明に載っている
- [ ] 操作説明は、ボタンで開いたり閉じたりできる

**優先度**: P0(必須)

### インターフェース

画面で操作するWebサイト。主なページは次のとおり。

| ページ | 内容 |
|---|---|
| トップページ | 会社情報（会社名・事業内容・実績・お知らせ） |
| ツール一覧ページ | 公開しているツールの一覧 |
| ポリゴンエリア定義ツール | 画像の読み込み、エリアの描画・編集、エリア定義JSONの出力・読み込み、操作説明 |

### 将来的な機能(Post-MVP)

#### 元に戻す / やり直す

ポリゴンエリア定義ツールで、直前の操作を取り消したり、やり直したりする。

**優先度**: P1(重要)

#### JSONをクリップボードにコピー

ファイルをダウンロードせずに、JSONをコピーしてコードに貼り付けられるようにする。

**優先度**: P1(重要)

#### 画像サイズが違うエリア定義JSONの読み込み

MVP では、画像の幅・高さが違うエリア定義JSONは読み込まない。P1 では、警告を出したうえで、確認すれば読み込めるようにする（範囲外になる座標の扱いは、そのときに決める）。

**優先度**: P1(重要)

#### 技術メモ

Markdownで書いた技術メモを置けるページ。壁打ちメモでは P1 だったが、本格的に育てるかが決まっていない（未決事項）ため、決まるまで着手しない P2 とする。

**優先度**: P2(できれば)

## 非機能要件

### パフォーマンス
- 画像の読み込み: 3840×2160（4K）の JPEG を選んでから表示されるまでが2秒以内（5回測った中央値） — 測定環境: 開発者のノートPC（Apple Silicon の MacBook）、Chrome 最新版、CPU を4倍遅くする設定（一般的なノートPCの代わり）
- 操作の反応: 4Kの画像に10エリア（合計100頂点）を設定し、拡大縮小・移動・頂点のドラッグを5秒ずつ行う間、16.7ms（60fps）を超えるフレームが全体の5%以下 — 測定環境: 同上
- 測定の手順の詳細は [architecture.md](architecture.md) の「パフォーマンス要件」を参照

### ユーザビリティ
- MVP公開前に、ツールを使ったことのない1人（社外の人でもよい）が、画面の操作説明だけを見ながら、テスト用の4K画像（`tests/fixtures/`）1枚にエリアを2つ描いてエリア定義JSONをダウンロードするまでを5分以内に終えられる。超えた場合は、つまずいた箇所の操作説明を直し、別の人で測り直す

### 信頼性
- エリア定義JSONの往復: 同じ画像を読み込んだ状態で、ダウンロードしたものを読み込み直して再びダウンロードしたとき、ファイルの内容が完全に一致する（自動テストで確認）

### セキュリティ・プライバシー
- 読み込んだ画像とエリア定義JSONを、どこにも送信しない: 画像を読み込む直前から、エリア定義JSONのダウンロード・読み込みを含む操作を終えるまでに、配信元を含む全ての宛先への http・https のリクエストが0件（`blob:`・`data:` は数えない。E2E テストで確認）

### 動作環境
- 対応ブラウザ: PC の Chrome・Edge の最新版（動作確認と E2E テストは Chrome で行う）。Firefox・Safari は動けばよく、動作は保証しない

### 運用コスト
- ホスティング費用: 月0円（GitHub Pages の無料の範囲に収める。そのためリポジトリは公開にする）

### 拡張性
- ツールの追加: 新しいツールを追加するとき、既存のツールのコードを変更しなくて済む

## スコープ外

- 現在のGoogleサイトにある「研究室」ページの引き継ぎ
- ブログ（Qiitaなど外部のサービスを使う）
- 問い合わせフォーム、連絡先（メールアドレスなど）の掲載（載せる情報は会社名・事業内容・実績・お知らせとした。連絡は名刺・メールで受ける）
- 現在のGoogleサイトにあるお知らせ2件（2017年）の引き継ぎ
- アノテーション（学習データ作成）用途の機能
- マスク画像の出力（出力はJSONのみ）
- ユーザー登録・ログイン、アクセス制限（ツールは全公開）
- サーバー側の処理（静的サイトとして公開する）
- ツールの集客・宣伝
- スマホ・タブレットでのツールの操作（会社のページは表示できればよい）
