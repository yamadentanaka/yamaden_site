# PRD 作成スキル

## 入力と出力

- 入力: `docs/ideas/` の壁打ちメモ（主に `initial-requirements.md`。`sample.md` は無関係なサンプルなので読まない）。メモがなければ、ユーザーとの対話で課題・ターゲット・主要機能・MVP の範囲を確認する
- 出力: `docs/product-requirements.md`。構造は [template.md](template.md) に従う
- 既存の PRD がある場合は、その構造と内容を優先し、変更箇所だけを更新する

## このプロジェクトでの決め事

- **優先度**:
  - P0（必須）: MVP に含める。これがないとプロダクトとして成立しない
  - P1（重要）: 初期リリース後すぐに追加する
  - P2（できれば）: 将来検討する
- **ユーザーストーリー**: 「[ユーザー]として、[目的]のために、[機能]が欲しい」の形式で書く
- **受け入れ条件**: チェックリスト形式。それぞれ、テストや操作で満たしたかを判定できる形で書く
- **KPI**: 指標・目標値・期限・測定方法をそろえる（SMART）
- **非機能要件**: 数値と測定条件で書く（悪い例: 「高速であること」 / 良い例: 「1,000件の一覧表示が1秒以内（一般的なノートPC）」）
- 壁打ちメモにない機能や数値を勝手に追加しない。推測で補った箇所は、確認が必要な点としてユーザーに伝える

## 品質基準

作成後に以下を自己確認し、満たしていない箇所を直してからユーザーに確認を求める。

- [ ] ビジョンと、ユーザーに提供する価値が具体的に書かれている
- [ ] ペルソナに、現在の課題と典型的な利用場面が書かれている
- [ ] KPI に目標値・期限・測定方法がある
- [ ] 全機能にユーザーストーリー・受け入れ条件・優先度がある
- [ ] 非機能要件が数値で書かれている
- [ ] スコープ外が明記されている
