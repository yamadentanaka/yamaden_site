# 用語集作成スキル

docs とコードで使う言葉を統一する（ユビキタス言語）。読み手が用語の意味と、コード上のどの名前に対応するかを、この文書で確認できる状態にする。

## 入力と出力

- 入力: `docs/` の他の5ファイル（存在するもの全て）。各ドキュメントから用語を抽出する
- 出力: `docs/glossary.md`。構造は [template.md](template.md) に従い、該当しないカテゴリは削除する
- 既存の用語集がある場合は、その構造と内容を優先し、追加・変更だけを行う

## このプロジェクトでの決め事

- **載せる用語**: プロジェクト固有の概念、このプロジェクトで特定の意味で使う一般語、略語、状態やエラーの種別。プログラミング一般の用語（変数、関数など）は載せない
- **定義**: 1〜2文で、他の用語と区別できるように書く。同じ概念に複数の呼び方がある場合は1つに決め、他を「使わない表記」として書く
- **コードとの対応**: 型名・モジュール名など、コード上の名前を併記する
- **状態**: 取りうる値と遷移の条件を書く。遷移が複雑なら Mermaid の状態遷移図を使う
- **エラー**: 発生条件と、ユーザーへの表示・対処を書く
- 用語はカテゴリごとに五十音順・アルファベット順に並べる

## 品質基準

- [ ] docs で使われている固有の用語が漏れなく載っている
- [ ] 各用語の定義が一意で、docs 内の使い方と一致している
- [ ] コード上の名前との対応がある（実装済みの場合）
- [ ] 略語に正式名称がある
- [ ] 状態の遷移条件、エラーの対処が書かれている
