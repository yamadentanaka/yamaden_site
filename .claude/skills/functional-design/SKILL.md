# 機能設計書作成スキル

PRD の「何を作るか」を「どう実現するか」に落とし込み、開発者が迷わず実装できる粒度にする。

## 入力と出力

- 入力: `docs/product-requirements.md`（必須）。P0 の機能を中心に設計する
- 出力: `docs/functional-design.md`。構造は [template.md](template.md) に従い、該当しないセクションは削除する
- 既存の機能設計書がある場合は、その構造と内容を優先し、変更箇所だけを更新する
- 技術スタックの選定は architecture.md の担当なので、ここには書かない

## このプロジェクトでの決め事

- 図は Mermaid で書く（システム構成図、ER図、主要ユースケースのシーケンス図、画面遷移図）
- データモデルは、プロジェクトで使う言語の型定義で書き、各フィールドに制約（必須/任意、文字数、形式など）をコメントで付ける
- スコア計算や推定などのアルゴリズムは、閾値・重み・分類の境界まで具体的な数値で決める
- インターフェース（CLI のコマンド・オプション・出力形式・終了コード、API のリクエスト/レスポンス、画面）は、外から見た挙動を全て書く
- エラーハンドリングは「エラー種別 / 処理 / ユーザーへの表示」の表で書く

## 品質基準

- [ ] PRD の P0 機能が全て、いずれかのコンポーネントとユースケースで実現されている
- [ ] データモデルの型と制約が明確
- [ ] 各コンポーネントの責務と依存先が明確
- [ ] アルゴリズムが数値まで決まっている（該当する場合）
- [ ] 想定されるエラーと、その扱いが網羅されている
