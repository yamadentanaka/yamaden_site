# アーキテクチャ設計スキル

PRD と機能設計書を技術的に実現するための、技術スタック・システム構造・非機能要件の実現方法を定義する。

## 入力と出力

- 入力: `docs/product-requirements.md`、`docs/functional-design.md`（いずれも必須）
- 出力: `docs/architecture.md`。構造は [template.md](template.md) に従い、該当しないセクションは削除する
- 既存の設計書がある場合は、その構造と内容を優先し、変更箇所だけを更新する

## このプロジェクトでの決め事

- **技術選定**: 全ての言語・ランタイム・ライブラリ・ツールに、バージョンと選定理由（このプロダクトの要件に照らした理由）を書く。バージョンはその時点の安定版を確認して書く
- **レイヤー**: 各レイヤーの責務と「許可される操作 / 禁止される操作」を書く。依存は上位から下位への一方向のみとする
- **非機能要件**: PRD の数値を、測定方法と測定環境まで具体化する
- **依存関係の管理**: バージョンの固定・範囲指定の方針を、ライブラリごとに理由付きで決める
- 開発ツール（テスト・lint・フォーマッタ・型チェッカー）の選定はここで行い、コマンドは development-guidelines.md に書く

## 品質基準

- [ ] 全ての技術選定にバージョンと理由がある
- [ ] レイヤーの責務と依存の方向が明確
- [ ] パフォーマンス要件に目標値・測定方法・測定環境がある
- [ ] セキュリティ（データ保護、入力検証、機密情報の管理）の方針がある
- [ ] データ増加と機能拡張への対応方針がある
- [ ] テスト戦略（種類・ツール・カバレッジ目標）がある
