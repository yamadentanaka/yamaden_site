# プルリクエスト作成（pr）

現在のリポジトリの変更を確認し、**コミット → push → プルリクエスト作成** までを
実行します。**デフォルトブランチ（`main`/`master`）上で作業していた場合は、
先に適切な作業ブランチへ切り替えてから** コミットします。

## 入力

- 第1引数（任意）: 関連する Issue 番号、または作業内容の簡単な説明。
  - 省略された場合は、変更内容（diff）からブランチ名・コミットメッセージ・PR内容を推測する。

## 前提

- `gh` CLI が認証済みであること（`gh auth status` で確認可能）。
- ターミナルコマンドはワークスペースルート（このリポジトリ）で実行する。

## 手順

### 1. 現在の状態を確認する
```bash
git status
git branch --show-current
git diff
git diff --staged
```
- ステージ済み・未ステージ・未追跡（untracked）の変更がいずれも無ければ、
  「コミットする変更がありません」と案内して終了する。
  - 手順4で `git add -A` を使うため、未追跡ファイルのみが存在する場合も
    「変更あり」として扱う（`git diff` / `git diff --staged` は空を返すが、
    `git status` に未追跡ファイルが現れる）。

### 2. デフォルトブランチを確認する
```bash
git symbolic-ref refs/remotes/origin/HEAD --short
```
- 取得できない場合は `main` → `master` の順にリモートに存在するか確認して判定する。

### 3. デフォルトブランチ上で作業していないか確認する
現在のブランチがデフォルトブランチ（`main`/`master`）と一致する場合、
**`main` ブランチへの直接コミットは許可しない**。以下の手順で作業ブランチに切り替える。

1. 変更内容（`git diff` / `git status` の変更ファイル）から、ブランチ名を提案する。
   - 命名規則: `feature/issue-<Issue番号>-<簡潔な説明>`（Issue番号が分かる場合）、
     または `feature/<簡潔な説明>`（不明な場合）。バグ修正であれば `fix/...` を使う。
   - `<簡潔な説明>` は変更内容を要約した英数字・ハイフン区切り（kebab-case）にする。
2. 提案したブランチ名をユーザーに提示し、承認または修正を得る。
3. 承認後、以下でブランチを作成・切り替える（未コミットの変更はそのまま引き継がれる）。
   ```bash
   git checkout -b <branch-name>
   ```
   - **注意**: 未コミットの変更は新ブランチにそのまま引き継がれるため、デフォルトブランチ上に
     元々あった今回の作業と無関係な変更も一緒に乗る。ブランチ名の承認待ちの間に変更が
     増えている可能性があるため、**この時点で `git status --short` を再実行** し、
     心当たりのないファイルが含まれていないか確認する（混入していた場合の対処は
     手順4に従う）。

現在のブランチがデフォルトブランチでない場合は、そのまま作業ブランチとして扱う
（切り替え不要）。

### 4. 変更をコミットする
- `git status` / `git diff` の内容から、日本語のコミットメッセージ案を作成する。
- 関連する Issue 番号が分かる場合は `Closes #<番号>` を含める。
- `git add -A` はリポジトリ全体をステージするため、**この時点で `git status --short` を
  再実行** し、その全出力（未追跡ファイルを含む）をコミットメッセージ案と併せて
  ユーザーに提示する。手順1の出力を再利用しないのは、手順3・手順4の承認待ちの間に
  ファイルが追加・編集されている可能性があるため。
- 今回の作業と無関係な変更が混ざっていた場合は、**stash・中断のどちらか** を選ばせる。
  - stash を選んだ場合は、対象を指定して退避してからコミットに進む。
    ```bash
    git stash push -u -m "pr: 今回の作業と無関係な変更を退避" -- <除外するファイル>...
    ```
    退避した変更は作業完了後に `git stash pop` で戻せる旨をユーザーに伝える。
  - 中断を選んだ場合は、作業ツリーを整理してから再実行するよう案内して停止する。
- 承認後、以下を実行する。
  ```bash
  git add -A
  git commit -m "<日本語のコミットメッセージ>"
  ```
- 既にすべてコミット済みで、未追跡ファイルも含めて変更が無い場合はこの手順をスキップする。

### 5. push する（要確認）
GitHub への push は不可逆操作のため、**実行前に必ずユーザーに確認を取る**。
承認後、以下を実行する（追跡ブランチが無い場合は `-u` を付ける）。
```bash
git push -u origin <branch-name>   # 初回 push の場合
git push                            # 既に追跡ブランチがある場合
```

### 6. プルリクエストを作成する
- まず既存 PR の有無を確認する。
  ```bash
  gh pr view --json url,state 2>/dev/null
  ```
  - 既に開いている PR があれば、「既に PR が存在します: `<URL>`。push した変更は
    このPRに反映されます」と案内し、新規作成はせず完了報告に進む。
- 既存 PR が無ければ、PR のタイトル・本文案を作成する。
  - タイトル: 変更内容を簡潔に要約した日本語1行。
  - 本文: 変更内容の要約（箇条書き）。関連 Issue があれば `Closes #<番号>` を含める。
  - タイトル・本文案をユーザーに提示し、承認を得る。
- **PR 作成は書き込み操作のため、実行前に必ずユーザーに確認を取る。**
  承認後、以下を実行する。
  ```bash
  gh pr create --title "<タイトル>" --body "<本文>" --base <デフォルトブランチ> --head <branch-name>
  ```

### 7. 完了報告
- 作成（または既存）の PR の URL を提示する。
- 切り替えたブランチ名（デフォルトブランチから切り替えた場合）、コミット内容、
  push の実施有無を要約する。
- 手順4で stash した変更がある場合は、`git stash list` の該当エントリと
  `git stash pop` で復元できる旨を完了報告に明示する（処理が続くうちに埋もれて
  戻し忘れることを防ぐため）。

## 注意

- `main`/`master` ブランチへの直接コミット・pushは行わない。必ず作業ブランチに
  切り替えてから作業する。
- `git push`・`gh pr create` は **書き込み・不可逆操作** のため、必ず事前にユーザーの
  確認を取ってから実行する。承認が得られるまで実行しない。
- コミットメッセージ・PR タイトル・本文はすべて **日本語** で書く。
- `gh` が未認証・リモートが未設定等のエラー時は、原因と対処を提示して停止する。
